# BENCHMARK TESTS

## OVERVIEW
`tests/` contains standalone, API-backed model benchmark programs rather than unit tests managed by pytest or unittest.

## STRUCTURE
| Path | Scope | Primary input |
|------|-------|---------------|
| `tests/test_p2/test_p2.py` | Compare LLM task extraction quality, coverage, and latency | `output/chunks.jsonl` |
| `tests/test_p5/test_p5.py` | Compare KG extraction/alignment/graph results across models and modes | `output/tasks.jsonl`, cached embeddings |
| `tests/sql_search.ipynb` | Exploratory SQL/search work | Local generated graph data |

## WHERE TO LOOK
- P2 benchmark defaults to `nemotron-3-ultra-free`, `deepseek-v4-flash-free`, `mimo-v2.5-free`, `hy3-free` and samples sessions from P1 chunks. Results are written as JSON and documented in the sibling Markdown reports.
- P5 benchmark runs `triple` and `entity` modes (same 4 models), isolates each run in a temporary Qdrant directory, and records extraction, alignment, graph, and total timing metrics.
- `test_p5_report.md` is auto-generated by `save_results`, but the generator currently covers entity mode only — triple-mode sections are absent. Treat `test_p5_models.md` (human-written) as the authoritative analysis.
- Both scripts prepend the repository `src/` directory to `sys.path`; preserve this when adding shared imports.

## COMMANDS
```bash
# Requires OPENCODE_ZEN_API_KEY and P1 output
python3 tests/test_p2/test_p2.py
python3 tests/test_p2/test_p2.py --models hy3-free nemotron-3-ultra-free
python3 tests/test_p2/test_p2.py --sessions 5 --concurrency 1

# Requires OPENCODE_ZEN_API_KEY, P2 tasks, and local embedding models
python3 tests/test_p5/test_p5.py --limit 5
python3 tests/test_p5/test_p5.py --modes triple
python3 tests/test_p5/test_p5.py --models nemotron-3-ultra-free deepseek-v4-flash-free
```

## CONVENTIONS
- Run benchmarks directly from the repository root with `python3`; there is no pytest discovery or assertion-based test suite.
- Set `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` before model imports when running without network access.
- Use `--limit` for smoke runs and explicit `--output` paths for new result sets; avoid overwriting reference reports unintentionally.
- P5 runs must use isolated Qdrant paths so entity collections from one model/mode cannot contaminate another run.
- Keep benchmark result schemas stable because the checked-in JSON and Markdown reports are comparison artifacts.

## ANTI-PATTERNS
- Do not run the full matrix casually: it makes external LLM calls and can be slow or expensive.
- Do not treat existing result JSON or logs as regenerated test output unless the benchmark was intentionally rerun.
- Do not add credentials, model responses containing secrets, or local databases to committed test artifacts.
